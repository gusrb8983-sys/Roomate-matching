## 1. 데이터 모양

### 사용자 (딕셔너리) — `data/users.csv`

| 키 | 뜻 | 형태 | 예시 |
| --- | --- | --- | --- |
| `user_id` | 사용자 ID | 글자 | `"u007"` |
| `nickname` | 닉네임 | 글자 | `"보통날"` |
| `gender` / `want_gender` | 성별 / 희망 상대 성별 | `"M"` 또는 `"F"` | `"M"` |
| `areas` | 희망 지역 | 글자 리스트 | `["명륜1가", "명륜2가"]` |
| `deposit_min`, `deposit_max` | 1인 보증금 범위 (만 원) | 정수 | `500`, `1000` |
| `rent_min`, `rent_max` | 1인 월세 범위 (만 원) | 정수 | `40`, `50` |
| `months` | 거주 기간 (개월) | 정수 | `12` |
| `move_in` | 입주 희망 시기 | `"연-월"` 글자 | `"2027-03"` |
| `smoke`, `pet` | 본인 흡연 / 반려동물 | True/False | `False` |
| `smoke_ok`, `pet_ok` | 상대 흡연 / 반려동물 허용 | True/False | `True` |
| `time`, `clean`, `noise`, `social` | 생활 패턴 (1~5) | 정수 | `3` |
| `chat_link` | 오픈채팅 링크 (수락 후 공개) | 글자 | `"https://..."` |

CSV에는 희망 지역이 `명륜1가;명륜2가`처럼 `;`로, 참/거짓이 `Y`/`N`으로 저장됩니다. `load_users()`가 위 형태로 바꿔 줍니다.

### 매물 (딕셔너리) — `data/properties.csv`

`property_id`, `name`, `dong`(예: `"명륜1가"`), `deposit`(전체 보증금, 정수), `rent`(전체 월세, 정수), `commute`(예: `"도보 8분"`), `house_type`

1인 부담액 = 매물 금액 ÷ 2

### 관심 등록 — `data/interests.csv`

`user_id`, `property_id`, `created_at`

### 매칭 요청 — `data/requests.csv`

`request_id`(예: `M001`), `from_id`, `to_id`, `property_id`(매물 없이 보낸 요청은 빈칸), `match_rate`, `status`(`대기` / `수락` / `거절` / `만료`), `created_at`, `updated_at`

### 정답 사례 — `data/test_pairs.csv`

`pair_id`, `user_a`, `user_b`, `expected`(`높음` / `낮음`), `note`

## 2. 함수

### 데이터 읽기·저장 — `src/data_io.py` (김민서)

| 함수 | 입력 | 출력 |
| --- | --- | --- |
| `load_users()` | 없음 | 사용자 딕셔너리 리스트 |
| `find_user(users, user_id)` | 사용자 리스트, ID | 사용자 또는 `None` |
| `save_user(user)` | 사용자 (새 사용자는 `user_id`를 `""`로) | 저장된 `user_id` |
| `load_properties()` | 없음 | 매물 딕셔너리 리스트 |
| `find_property(properties, property_id)` | 매물 리스트, ID | 매물 또는 `None` |
| `add_interest(user_id, property_id)` | 사용자 ID, 매물 ID | 새로 등록하면 `True`, 이미 있으면 `False` |
| `remove_interest(user_id, property_id)` | 사용자 ID, 매물 ID | 없음 |
| `get_interested_user_ids(property_id)` | 매물 ID | 사용자 ID 리스트 |
| `add_request(from_id, to_id, property_id, match_rate)` | 요청자, 대상자, 매물 ID(없으면 `""`), 일치율 | 요청 번호, 같은 대기 요청이 있으면 `None` |
| `update_request_status(request_id, status)` | 요청 번호, `"수락"`/`"거절"`/`"만료"` | 성공하면 `True` |
| `get_requests_for(user_id)` | 사용자 ID | (받은 요청 리스트, 보낸 요청 리스트) |

### 매칭 — `src/matching.py` (김란)

| 함수 | 입력 | 출력 |
| --- | --- | --- |
| `fits_property(user, prop)` | 사용자, 매물 | 맞으면 `None`, 아니면 사유 (`"희망 지역"` / `"예산"`) |
| `is_excluded(a, b, prop=None)` | 사용자 A, B, 매물(선택) | `(True, 사유)` 또는 `(False, "")` |
| `calc_importance(user, item)` | 사용자, 항목 이름 | 중요도 (정수) |
| `calc_match_rate(a, b)` | 사용자 A, B | `(일치율, 항목별 유사도 딕셔너리, A 입장 점수, B 입장 점수)` |
| `recommend_for_property(me, prop, users, interested_ids, skip_ids=None)` | 나, 매물, 전체 사용자, 관심 등록자 ID, 뺄 ID | `{"my_reason": ..., "results": [...], "excluded": {...}}` |
| (예정) 룸메이트에서 출발하는 추천 | 나, 전체 사용자, 전체 매물 | 상위 5명과 각자의 공통 매물 |
| (예정) 매칭 요청·수락·거절 처리 | — | — |

`recommend_for_property`의 `results` 한 칸: `{"user": 사용자, "rate": 78.5, "similarity": {"time": 0.5, ...}, ...}`

### 화면 — `src/app.py` (이동욱 화면, 최현준 통합)

화면은 위 함수만 불러서 씁니다. 화면에서 CSV를 직접 읽거나 쓰지 않습니다.
