# 진행 중 겪은 문제와 해결 기록 (최종 보고서용)

## 문제 1. 공공데이터로는 현재 매물을 구할 수 없음 (중간보고서 반영 완료)

- **상황**: 국토교통부 전월세 실거래가로 추천 매물을 제공하려 했으나, 공개 데이터는 계약이 끝난 거래 기록뿐이었다.
- **해결**: 실거래가를 '시세 기준'으로 쓰고, 그 시세에 맞춘 가상 매물 20건을 만들었다.

## 문제 2. 가상 데이터의 보증금이 실제 시세보다 높음 (중간보고서 반영 완료)

- **상황**: 처음 만든 가상 매물과 가상 사용자의 보증금이 실제 시세(1인 약 250~1,000만 원)보다 높게 잡혀 있었다. 매물과 사용자 예산이 함께 높아 서로는 맞물렸기 때문에 문제가 드러나지 않았다.
- **발견**: 국토부 실거래 자료로 동별 시세표를 만들어 가상 데이터와 비교하면서 알게 되었다.
- **해결**: 매물 가격을 동별 중앙값 기준으로 다시 정하고, 사용자 보증금 범위를 절반으로 낮췄다. 한쪽만 고치면 서로 어긋나므로 두 데이터를 함께 고쳤다.

## 문제 3. 지역까지 따지면 서로 맞는 매물·사용자가 없음 (2026-11-02 발견)

- **상황**: 데이터 최종본을 만든 뒤, 실제 함수(`fits_property`)로 모든 사용자 × 모든 매물 조합을 판정해 보았다.
  - 매물 20개 중 7개(P008, P009, P012, P013, P016, P018, P019)는 희망 지역과 예산이 모두 맞는 사용자가 0명이었다.
  - 사용자 20명 중 7명(u003, u005, u006, u009, u011, u015, u016)은 자기에게 맞는 매물이 0개였다.
  - 이대로면 이 사용자로 시연할 때 "맞는 매물이 없다"는 결과만 나오고, 룸메이트에서 출발하는 경로에서도 함께 살 매물이 제시되지 않는다.
- **원인**:
  - 매물 데이터와 사용자 데이터를 따로 만들고, 두 데이터를 서로 대조해 보지 않았다.
  - 앞서(문제 2) 데이터를 점검할 때 예산만 확인하고 희망 지역은 함께 확인하지 않았다.
  - 예산이 낮은 사용자들이 시세가 높은 혜화동·동숭동만 희망 지역으로 갖고 있었다. 실제로 싼 집은 학교 바로 앞의 명륜3가와 창신동에 많다(시세표 참고).
- **해결**: 실제로 싼 집을 찾는 사람이 보는 지역을 반영해, 7명의 희망 지역과 일부 월세 범위를 조정했다.

| 사용자 | 바꾼 내용 | 맞는 매물 (전 → 후) |
| --- | --- | --- |
| u003, u011, u016 | 희망 지역에 명륜3가 추가 | 0개 → 3개 (P003, P006, P012) |
| u006 | 희망 지역에 명륜3가, 창신동 추가 | 0개 → 2개 (P013, P018) |
| u009 | 희망 지역에 종로6가 추가, 월세 35~45 → 30~40 | 0개 → 2개 (P008, P016) |
| u005 | 월세 45~60 → 40~55 | 0개 → 2개 (P009, P019) |
| u015 | 희망 지역에 동숭동 추가, 월세 45~55 → 40~50 | 0개 → 2개 (P009, P019) |

- **결과**: 모든 사용자에게 맞는 매물이 1개 이상, 모든 매물에 맞는 사용자가 1명 이상 생겼다. 생활 패턴은 바꾸지 않았으므로 계산 예시(u007·u017, 78.5점)와 정답 사례 결과는 그대로다.
- **교훈**: 여러 데이터를 따로 만들 때는, 실제로 쓸 함수로 모든 조합을 한 번 돌려 서로 맞물리는지 확인해야 한다. 표만 눈으로 보면 놓치기 쉽다.

## 기타 메모

- 정답 사례 중 일치율이 낮은 두 쌍(T3, T4)은 모두 u001을 포함한다. 조건을 모두 통과하는 쌍 중 일치율이 가장 낮은 쌍이 이 둘뿐이었기 때문이다.
